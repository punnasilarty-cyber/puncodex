a comprehensive loading library

ชุดคอมโพเนนต์และกฎการโหลดที่ใช้จริงทั้งในแอป Flutter และเว็บของ Pun Codex — skeleton ที่มีโครงเหมือนของจริง, สามสถานะการโหลดที่ความหมายชัดเจน, และกติกาที่ทำให้ ไม่มีจอว่าง ไม่มีการกระพริบ และไม่มีเลย์เอาต์กระโดด

Overview

ระบบนี้ไม่ได้มีแค่ spinner — มันกำหนดว่าแต่ละสถานะ “หมายถึงอะไร” และหน้าจอต้องแสดงอะไร ทุกครั้ง เพื่อให้ผู้ใช้ไม่ต้องเดาได้ว่าแอพกำลังทำอะไร

1 · เนื้อหามาก่อน

Skeleton วาดโครงของเนื้อหาจริง — กริดเดียวกับของจริง ความสูงแถวเท่ากัน → ข้อมูลมาถึงแล้วไม่มีอะไรกระโดด

2 · ไม่ลบสิ่งที่ผู้ใช้กำลังอ่าน

การรีเฟรชไม่เคยแทนที่เนื้อหาด้วย spinner — เนื้อหาเดิมอยู่ พร้อมแถบบาง 3px ด้านบน

3 · ขั้นต่ำ 320 ms

ข้อมูลที่มาก่อน 320 ms จะไม่ทำให้เกิดการกระพริบสีเทา — skeleton อยู่ครบเวลาขั้นต่ำ

4 · สีจากธีม ไม่ใช่เทาตายตัว

พื้น skeleton คือพื้นผิวของธีมผสม primary 10–16% → ดูตั้งใจทั้งโหมดสว่างและมืด

Getting Started

ใช้งานได้สองทาง: ในแอป Flutter (คอมโพเนนต์จริง) และบนเว็บ (สเปก CSS เดียวกัน)

Flutter

// 1) import
import 'package:surawit_photo_archive/widgets/skeleton.dart';

// 2) ครอบส่วนที่กำลังโหลด
AsyncSection(
  phase: phase,                       // initial · refreshing · ready · error
  skeleton: const SkeletonList(count: 5),
  error: error,
  onRetry: _load,
  child: content,                     // child ต้องอยู่ท้ายสุด
)

Web (CSS)

/* พื้นที่ที่กำลังโหลด */

Components

10 primitive ที่ใช้ซ้ำทั้งแอป — ชื่อเดียวกับที่อยู่ในโค้ด Flutter

SkeletonLine / SkeletonParagraph

แทนข้อความหนึ่งบรรทัด / ย่อหน้า — บรรทัดสุดท้ายสั้นกว่าตามธรรมชาติ

SkeletonListTile

แถวรายการ: วงกลม/สี่เหลี่ยมนำ + สองบรรทัด + ปลายขวา (badge)

SkeletonAlbumGrid

การ์ดอัลบั้ม 2 คอลัมน์ — รูป + ชื่อ + จำนวน

SkeletonPhotoGrid

กริดรูป 3 คอลัมน์ (สัดส่วน 1:1) — ใช้ในอัลบั้มและคลังภาพออนไลน์

SkeletonCard

การ์ดข้อมูล: หัวข้อ + แถว label/value (ใช้ตอนโหลด API/การตั้งค่า)

SkeletonGroup

ครอบทั้ง tree ให้ใช้ animation ตัวเดียว — ประหยัดเฟรม

Skeletons

Skeleton ทุกตัว “คัดลอกเลย์เอาต์จริง” — กริดเท่ากัน ระยะห่างเท่ากัน จึงไม่มี layout shift

ก่อนข้อมูลมา

แสดง skeleton ที่มีโครงเหมือนจอจริง

หลังข้อมูลมา

การ์ดจริงในตำแหน่งเดิม — ไม่มีการกระโดด

Loading States

สามสถานะ ความหมายเดียว ใช้ทุกหน้า — กดเพื่อดูของจริง

Stateเมื่อไรผู้ใช้เห็น
initialยังไม่มีอะไรบนจอSkeleton ที่มีโครงเหมือนของจริง (ขั้นต่ำ 320ms)
refreshingมีเนื้อหาอยู่แล้วเนื้อหาเดิม + แถบ 3px ด้านบน
errorโหลดล้มเหลวการ์ดข้อความ + ปุ่ม “ลองอีกครั้ง”
readyข้อมูลมาแล้วเนื้อหาปกติ

Accessibility

โหลดที่ “ไม่ทำให้ผู้ใช้รู้สึกแย่” คือ accessibility ในทางปฏิบัติ

Reduced motion

ทุก animation ปิดเมื่อระบบตั้ง prefers-reduced-motion — ในแอปใช้ MediaQuery.disableAnimations

Contrast

ข้อความบนพื้น skeleton ใช้สี ink ที่ 70–100% — ผ่าน AA ที่ขนาด ≥ 13px

ไม่ใช้สีอย่างเดียว

สถานะ error มีไอคอน + ข้อความ ไม่ได้สื่อด้วยสีแดงเท่านั้น

Focus & keyboard

ปุ่ม/ช่องกรอกเรียง Tab ตามสายตา, Enter ส่งฟอร์ม, Esc ปิด dialog

ขั้นต่ำ 320ms

ป้องกันการกระพริบที่เป็นอันตรายต่อผู้ไวต่อแสง

ประกาศสถานะ

บนเว็บใช้ aria-busy ระหว่างโหลด และ role="status" กับข้อความ error
